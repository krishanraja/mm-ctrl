# G25 operator route readiness, R139 strategy

## Outcome

Make it impossible to connect the private Decision Bench to a real selected-customer URL while any important part of the surface is synthetic, inferred from URL text, authenticated against another environment or unbound to the same decision.

## Why this gate exists

R138 proved one narrow live seam: an authorised operator can receive one five-field review signal from the isolated project and render it inside the approved instrument. The rest of the instrument still comes from the Maya Chen synthetic fixture and static route, challenge, source-group and Claude-brief logic.

Connecting that mixed composition to a real customer route would be false confidence. It could place a live private question inside a synthetic customer, decision and evidence story. A route must therefore be earned by a complete same-workspace, same-decision and same-environment projection.

## Governing rule

The route is ready only when all of these are simultaneously true:

1. An exact feature gate is enabled.
2. The runtime URL and project identity are exactly the isolated project and are distinct from production.
3. The route uses a dedicated runtime client, never the global production product client.
4. A non-anonymous authenticated human resolves to a valid stable operator principal in that same project.
5. The selected workspace is a valid UUID and is verified by the server, not trusted because it appeared in the URL.
6. The complete decision projection is live, valid and bound to that workspace, decision and environment.
7. The review projection is live and bound to the same workspace, decision and environment.
8. Every failed condition returns no route and every relevant reason, so the next dependency cannot hide behind the first error.

## Authority

This gate may add a pure readiness evaluator, adversarial tests, machine evidence and durable planning. It may not add a route, connect the global client, create a customer-facing surface, mutate a database, deploy, merge or release.

## Pass signals

- One fully bound live isolated input produces one exact route.
- The current R138 mixed synthetic and live state is explicitly blocked.
- Production targeting, lookalike URLs, anonymous sessions, auth-environment mismatch, missing stable principal, URL-only workspace selection, synthetic or missing projections and cross-workspace, cross-decision or cross-environment material all fail closed.
- Multi-failure input returns the complete ordered reason set.

## Next safe action

Define and prove the complete live operator decision projection. It must replace every synthetic dependency that can steer what Krish sees or sends, not merely relabel the current fixture. Route connection remains closed until that projection is both strict and live.
