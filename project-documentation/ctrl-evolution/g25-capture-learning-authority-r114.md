# G25 owner-governed capture and learning R114

R114 proves that runtime evidence can suggest a sharper standard without silently becoming the standard. It closes the weekly proposal loop on the isolated Legibility project and leaves every production, scheduling, merge, cutover and retirement gate closed.

## What can become a proposal

The pass reads the owner-selected cadence, evidence window, unique-evidence threshold and proposal limit. A changed answer or retry from one review keeps the same source identity and cannot manufacture recurrence. Uncovered patterns stay inside one work surface. A possible stale rule is raised only after enough applicable work on that surface has actually been reviewed; unknown exposure remains unknown.

Each proposal pins the current standard, exact source snapshot, evidence locators, alternative explanations, expected effect, validation plan, privacy boundary, dependencies, rollback and measurement plan. Raw review quotes remain in the private source and are not copied into the durable proposal packet.

## What cannot happen

The route can write only proposal packets. It cannot edit criteria, standards, skills or releases. An owner decision requires the exact proposal hash and an explicit scope. A drift proposal also requires an explicit choice to retain, revise, gather evidence or retire. Acceptance writes an append-only decision event and returns `change_applied=false`; the next state is a versioned change request.

The size obligation no longer deletes an unrelated rule simply because one was added. It can recommend replacement, progressive disclosure or a split only when the evidence justifies that move. A reused holdout remains regression evidence and can never create a fresh measurement claim.

## Hosted result

The isolated hostile probe published one drift question and one repeated false-positive proposal from two independent review events. Exact replay returned the same capture run. A new week inside the owner's seven-day cadence returned `not_due`. The owner could update their own policy and another owner could not. Direct proposal updates and cross-owner decisions failed. Accepting the proposal left the criteria bytes unchanged. A stale snapshot could not publish, and cleanup left zero synthetic users, capture runs or proposals.

## Boundary

This proves the authority and evidence mechanics on synthetic data. It does not prove that a proposed change is valuable for a real leader, that the customer interaction is good, or that the scheduled operation is ready. No cron was created. Production was not mutated. No merge, cutover, release, legacy retirement or old development-project deletion is authorised.
