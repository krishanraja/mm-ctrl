## One closed language

Every schema type now resolves through one explicit registry. SHA-256, UTC timestamps, unpadded base64url, bounded integers, operation-discriminated intent and the extensible controlling-watermark union all have executable definitions. Every schema, enum, member and fingerprint reference must resolve. The generator fails before JSON serialization if any value is undefined.

Canonical field encoding is exact. Strings and enums use length-framed UTF-8. Hashes use 32 raw bytes. Integers use unsigned 64-bit big-endian bytes. Booleans use one byte. Arrays carry a count followed by encoded items. Optional absence and presence use distinct one-byte tags. Objects follow declared schema field order. Unspecified maps and generic JSON values are forbidden.

## Registry lookup separates fresh execution from replay

Streaming limits, authentication sufficient to resolve stable identity and workspace, request shape and canonical fingerprint complete first. The system then looks up `(workspace_ref, operation_id)`.

- No row opens fresh current authority, evaluation and snapshot compare-and-swap.
- The same committed binding opens disclosure checks only and returns the historical replay envelope.
- A different binding rejects without protected bytes or mutation.

Replay never reruns current operation authority, the evaluator, snapshot compare-and-swap or any protected mutation. A malformed request is a rejection, not a dangling held result. A post-admission snapshot mismatch is the defined `snapshot_changed_hold`.

## Seventeen registered operations

R7 adds server issuance of an intervention presentation challenge to the sixteen R6 operations. It has the same registry, authority, replay, limits, immutable result and snapshot treatment as every other write.

The product action remains `edit`. Its trusted execution is stage, actual foreground presentation, explicit human acknowledgement and later approval. The challenge binds case, viewer, atom, version, content fingerprint, server nonce and a five-minute expiry. Issuing, generating, prefetching, background loading or hidden rendering content is not presentation. A currently bound human must act after the exact content is foregrounded. No workload or telemetry event can acknowledge for them.

## Branch effects are exact

Approval, hold and suppress each declare their own reads, writes and forbidden writes. Every branch consumes the exact visibility acknowledgement atomically, while only approve creates approval. Release use has two disjoint branches: current watermarks create a use receipt and pending outbox effect; changed watermarks create only an idempotent invalidation receipt and explicitly forbid an outbox. Single-human lifecycle transitions forbid joint consumption; two-party transitions atomically append it with the transition and snapshot.

## Lifecycle authority is immutable

Action and joint receipts contain no mutable consumption timestamp. Action combination and joint transition consumption are separate append-only records with unique keys. The contract defines outcomes for the same nonce with the same bytes, the same nonce with different bytes, the same action pair and either action already paired elsewhere.

A fresh two-party transition requires unexpired action and joint receipts, recomputed fingerprints, authority versions equal to current case bindings, exact action-combination rows, no prior joint-transition consumption and exact case, transition and predecessor equality. Replay still uses disclosure authority only.

## Proof ownership is row exact

Each of the eight proof families now identifies one canonical owner table and schema, the owner row reference and fingerprint fields, the exact extension fields they equal, every additional authoritative row, current-at-snapshot rules, scope equalities and one failure code. The server resolves and fingerprints those rows inside the evaluator's serializable transaction. The caller and browser provide neither proof bytes nor row choice.

## Fingerprints are stable

Thirteen authority-bearing record families use the same exact field encoding, one domain, a complete ordered field list and explicit self-field exclusion. Lifecycle issue receipts never mutate when consumed. Presentation challenges, visibility acknowledgements, lifecycle consumption and each outbox event have their own domains.

## Outbox history cannot forget dispatch

Claims, reservations, dispatches, terminal observations and reconciliations are append-only events. A reservation receives ordinal one, two or three. One immutable dispatch consumes it before exactly one possible provider call. Every success, failure, ambiguity and reconciliation record binds the exact dispatch, ordinal, fence, worker, provider operation, key and payload fingerprint.

If a worker reports an unknown outcome, or its dispatch-bound lease expires without terminal evidence, an immutable ambiguity event is appended. A reaper never calls the provider. A new reservation is allowed only when the provider's current idempotency guarantee holds and fewer than three reservations exist. Otherwise the effect becomes unknown. Reconciliation may later confirm or fail that exact dispatch but can never send. A worker or lease change never resets the count.
