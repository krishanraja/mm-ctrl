# CTRL context circulation architecture

**Status:** Locked governing product architecture (founder-approved 2026-09-07)

**Phase:** Founder alignment moving into corpus and architecture

**Scope:** How useful context enters the brain, becomes trustworthy and returns to the leader's work

**Not authorised:** Visual lock, implementation, provider selection, production connectors or cross-user sharing

## The correction

CTRL should not ask the leader to choose a single doorway into their brain.

That question mistakes an implementation sequence for the product model. The founder has already specified the governing experience: flexible and predictive; AI performs the heavy lifting; transcript quality is sacrosanct; one tap or voice should be available when useful; and the system should behave like a thoughtful working partner without demanding technical knowledge or persistent cognitive effort.

The product model is therefore **context circulation**:

> Important work can reach CTRL through the natural moment in which it occurs. CTRL privately determines what may matter, asks only when uncertainty changes the meaning, proposes what should endure, and returns the smallest useful piece of intelligence where the leader can act on it.

There is one brain and one trust model beneath several entry and return moments. The user experiences continuity, not integrations.

## Experience contract

The leader should be able to:

- finish a meeting and discover that CTRL has prepared the decisions, tensions, commitments and possible standards worth reviewing;
- send a thought, screenshot, message, document or voice note when something feels important without classifying it first;
- begin consequential work and find the relevant prior judgement, correction, evidence or contradiction already in scope;
- let CTRL request one missing source or clarification when it would materially change the result;
- correct CTRL once and have every affected future use repaired;
- see what CTRL proposes to remember, why, where it came from, who can see it and what it will influence;
- move a suitable output into the work with one deliberate action; and
- take the brain with them in a human-readable and machine-usable form.

They should not need to understand retrieval, embeddings, connectors, schemas, prompt design or memory tiers.

## One circulation system, four ways context arrives

These modes coexist. CTRL selects or suggests the lowest-friction eligible route from the user's current situation; it does not make the user configure a personal data pipeline before receiving value.

### 1. Work exhaust

Authorised activity that already creates a useful record can quietly feed the private staging area:

- Mindmake and leadership meeting transcripts;
- decisions, corrections and agreed actions from CTRL sessions;
- selected completed work and its feedback;
- outcomes attached to earlier decisions; and
- approved company or category evidence streams.

This is the richest route because it captures judgement in context. It is not permission to record every call, message or click.

### 2. A deliberate signal

When the leader notices something first, the gesture is intentionally primitive:

- speak it;
- share it to CTRL;
- paste it;
- forward it;
- upload it; or
- say “keep this,” “challenge this,” or “use this later.”

CTRL performs classification, provenance capture, deduplication and suggested scope. The leader supplies meaning, not metadata.

### 3. Just-in-time retrieval

During real work, CTRL may detect a material context gap and ask for the smallest source that could change the answer: a specific document, the latest numbers, a prior decision or permission to inspect an eligible connected surface.

The request must explain the consequence in plain language. “I can give you a much stronger view if I check the latest forecast” is useful. “Connect your Drive to improve personalisation” is not.

### 4. Deliberately scoped streams

A leader may choose ongoing access to a bounded source when repeated value is proven: a meeting series, folder, project, inbox label, CRM view or category signal set. Scope is expressed in recognisable work terms and can be paused or withdrawn from the same place where its value appears.

Blanket access is never the default doorway.

## The universal context envelope

Every source becomes the same typed envelope before any model can treat it as memory:

| Field | Purpose |
|---|---|
| Source and locator | Lets the user and system return to the evidence rather than trust a detached summary. |
| Captured time and event time | Separates when CTRL saw something from when it was true. |
| Subject and speaker | Prevents another person's words or a meeting summary from becoming the leader's belief. |
| Ownership and audience | Distinguishes personal, company, client, project and potentially shareable context. |
| Permission and purpose | Records why this source may be used and what uses remain outside scope. |
| Evidence class | Separates direct statement, observed behaviour, external fact, model inference and generated suggestion. |
| Freshness and expiry | Stops old numbers, roles or intentions becoming current truth. |
| Sensitivity and third-party presence | Drives minimisation, retention and whether durable extraction is eligible at all. |
| Confidence and consequence | Determines whether CTRL can act quietly, must ask, or must abstain. |
| Provenance chain | Preserves the path from source to claim, memory, output and later correction. |

The envelope is the architecture's centre of gravity. Connectors are replaceable adapters into it.

## From raw context to a living brain

CTRL does not pour source material directly into a permanent memory store. It runs a governed interpretation loop:

```text
authorised source
  → private staging
  → context-quality and ownership checks
  → candidate claims and relationships
  → contradiction and freshness checks
  → proposed durable residue
  → human correction, confirmation or quiet expiry
  → scoped memory
  → use in later work
  → outcome, rejection or correction
  → repair every affected downstream use
```

### What CTRL can propose to retain

- **Decision:** what was chosen, why, by whom and what would reopen it.
- **Criterion:** the standard used to judge work or choose between options.
- **Taste signal:** an admired or rejected example and the reason, not a vague adjective.
- **Correction:** what CTRL got wrong and which future behaviours must change.
- **Tension:** two truths that should not be prematurely resolved.
- **Evidence:** a source-bound fact with freshness and uncertainty.
- **Pattern:** a recurring mechanism that may generalise, with counterexamples.
- **Commitment:** an owned next move whose operational state remains in its proper work system.
- **Outcome:** what happened after a decision, including ambiguity and luck.
- **Open question:** the smallest unresolved issue capable of changing the route.

The brain retains negative evidence as first-class material: rejected ideas, broken examples, disliked writing patterns, failed predictions and conditions under which a usually good rule should not apply.

## Memory states the user can understand

| System state | Human meaning | Allowed behaviour |
|---|---|---|
| Staged | “CTRL is privately making sense of this.” | Short-lived, private, source-bound; cannot silently steer unrelated work. |
| Suggested | “This may be worth keeping.” | Can appear as a lightweight proposal with reason, source and likely future use. |
| Held | “Use this carefully for now.” | Provisional and contradiction-aware; appropriate for low-consequence assistance. |
| Trusted | “This is part of how I work or decide.” | May be recalled across eligible contexts with provenance and correction controls. |
| Shared candidate | “This may help others without exposing me.” | Remains private until the leader approves the exact de-identified item. |
| Shared pattern | “I approved this contribution.” | Enters the permissioned commons with scope, provenance, withdrawal and downstream repair. |
| Retired or disputed | “Do not rely on this as current.” | Preserved for lineage where lawful, excluded from current guidance and visibly linked to its replacement. |

Most routine transitions can be inferred privately. Promotion into trusted high-consequence use, expansion of audience and collective contribution receive proportionate human authority.

## How intelligence returns to the work

CTRL should not produce a generic stream of “memories.” It returns one of five useful interventions:

1. **Recall:** “You decided this before, under these conditions.”
2. **Contrast:** “This conflicts with a standard or earlier belief you care about.”
3. **Completion:** “The source gives us most of the picture; this missing fact could change the call.”
4. **Preparation:** “I used what I know to prepare genuinely different, evidence-bearing options before you arrived.”
5. **Reflection:** “The outcome or your correction suggests this part of the brain should change.”

The intervention appears in the natural destination: meeting preparation, a decision conversation, a draft, a briefing, a voice interaction or a deliberate “use in…” action. Delivery into another system is distinct from granting that system access to the whole brain.

## The orchestration policy

For every possible intervention, CTRL decides in this order:

1. **Is it allowed?** Confirm subject, purpose, ownership, audience and third-party boundary.
2. **Is it supported?** Verify provenance, freshness and whether the source actually establishes the claim.
3. **Is it relevant now?** Connect it to the current decision, work or stated priority.
4. **Could being wrong matter?** Raise the confirmation and evidence bar with consequence.
5. **Is interruption earned?** Surface only if it changes a decision, prevents a meaningful error, preserves a standard or creates disproportionate value.
6. **What is the smallest useful form?** Recall one criterion before retrieving a dossier; ask one precise question before opening an interview.
7. **What should happen afterward?** Record use, rejection, correction or outcome so the brain becomes more calibrated rather than merely larger.

This is where “magic” lives: orchestration makes technical complexity disappear while epistemic status remains honest.

## Context quality is sacrosanct

CTRL must not infer any of the following merely because text appeared in an authorised source:

- that a speaker's statement is the leader's belief;
- that a proposal became a decision;
- that repetition means truth or endorsement;
- that a meeting summary preserves disagreement;
- that an old number is current;
- that a copied message may be reused outside its original audience;
- that a model-written sentence is evidence about the user; or
- that access permission is permission to publish or share.

When the distinction changes the result, CTRL asks precisely. When it does not, it keeps the ambiguity attached and avoids unnecessary interruption.

## Minimum credible multi-door experience

The first product proof should not be a connector marketplace. It should make three naturally different moments feel like one intelligence:

1. **After the room:** an authorised meeting transcript becomes a small set of proposed decisions, tensions, standards and next questions.
2. **At the moment:** a single text, voice, share or upload surface accepts anything important without asking the leader to classify it.
3. **Before the work:** a decision or prepared-work surface recalls the relevant prior judgement, asks for one missing source if necessary and produces an evidence-aware intervention.

All three run through the same context envelope, memory states and correction lineage. Technically, the first build may use transcript upload, a universal capture composer and the existing decision surface rather than multiple production integrations. The perceived product remains multi-door; the implementation remains small enough to test.

## What not to build

- A sync dashboard that makes the leader administer integrations.
- A universal activity firehose.
- A folder of undifferentiated memories.
- A chatbot that searches everything only when explicitly asked.
- A daily interruption justified by having found something “interesting.”
- Automatic promotion from repeated text to durable truth.
- Automatic cross-user sharing under blanket consent.
- A separate memory system for every product surface.
- A technical graph visual presented as proof that CTRL understands someone.

## Proof and failure conditions

The architecture is working when a leader can move through different work moments without thinking about capture mechanics, yet can accurately understand and correct what CTRL believes and why it surfaced something.

Candidate leading measures:

- **Decision-useful recall precision:** surfaced context judged material to the live task, not merely related.
- **Correction survival:** a correction is reflected everywhere it should influence future work.
- **Held-out lift:** prior brain context improves genuinely new work against a no-brain baseline.
- **Interruption yield:** the share of interruptions that change a call, prevent an error or produce an explicitly valued next move.
- **Context provenance coverage:** consequential claims retain source, subject, time, scope and epistemic status.
- **Return pull:** the leader voluntarily brings a new real work moment into CTRL.

The design fails if it requires the user to maintain the brain, converts convenient transcripts into false certainty, becomes creepier as it becomes more capable, retrieves related-but-useless history, loses corrections across surfaces or makes every experience feel like the same AI-generated template.

## Remaining founder-owned decisions

These should be resolved through concrete scenarios or rendered behaviour, not more abstract intake questions:

- how visibly CTRL should announce quiet preparation after a meeting;
- when a memory proposal deserves interruption versus passive availability;
- what a correction and downstream repair receipt should feel like;
- how much proactive contradiction feels thoughtful rather than argumentative;
- what contribution to the shared pattern commons feels rewarding rather than extractive; and
- which external work surfaces earn production adapters after the underlying loop proves value.

The next step is to turn this architecture into three deliberately different interaction spines for the first five-minute loop, judge their conceptual distance and feasibility, and show the founder one rendered synthesis. Visual work remains behind the existing approval gate.
