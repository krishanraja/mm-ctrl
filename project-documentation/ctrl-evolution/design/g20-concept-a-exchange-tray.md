# G20 concept A: The Exchange Tray

**Concept revision:** A-01  
**Evidence boundary:** G20 sanitized brief and its named state route only  
**State of use:** Private capture and Claude handoff inside one active customer Brain  
**Materiality:** Material interaction concept  
**Authority:** Concept document only. No render, implementation, connector change, data write or release is authorised  
**Approval state:** Proposed and unrendered  
**Rendered evidence:** None  
**Downstream owner:** G20 blinded judging and synthesis  
**Pending action:** Test whether a cold viewer can complete the synthetic capture, handoff and return loop without explanation

## Design task contract

**STATE OF USE:** Krish is between customer work on desktop or steering from mobile. He has one piece of useful material and wants it safe or useful in Claude now. He is busy, knows which customer he is working on and will not tolerate setup or a form.

**USER + ACTION:** Krish places one fragment into private staging, checks the receipt, passes only a named slice of Maya's Brain to Claude for one purpose and brings one result back as attributed staged material.

**GOVERNING RULE:** One physical tray carries one exchange. The active customer, private boundary and retained receipt stay fixed outside the moving tray. Nothing crosses the boundary until Krish performs the action shown beside the exact contents and purpose.

**DATA TRUTH:** The proof uses only synthetic Maya Chen data, the current Decision Bench objects, explicit source and audience fields, deterministic capture outcomes and a read-only Claude context path. Missing meaning remains missing. A return is labelled as a Claude suggestion supplied by Krish and never as verified fact or trusted memory.

**MATERIALITY:** Material. This is a new context-circulation surface and needs blinded selection, one rendered proof and an explicit founder gate before implementation.

**BRAND + VOICE:** Preserve the approved dark, warm, instrument-like environment and icon-only shell. Mint marks current answer or safe completion. Amber marks newly received or changed material. Visible copy is plain and performs one action, state, limit or meaning job.

**AUTHORITY:** Concept documentation only. Production accounts, customer data, schema, connector deployment, feature enablement, trusted-memory writes, main-branch release and public navigation remain closed.

**PROOF:** A later synthetic proof must cover the complete loop and every required adverse state at 1440 by 900, 390 by 844 and 320 by 568, with keyboard, touch, visible focus, 44 px controls, reduced motion, no nested scrolling and no active-looking dead control.

## 1. Governing metaphor

The surface is a physical exchange tray set into the approved Decision Bench. It behaves like a shallow pass-through drawer with three labelled resting places:

1. **Keep here:** private staging inside CTRL.
2. **Use in Claude:** a purpose-bound selection crosses to Claude for a limited time.
3. **Bring back:** one Claude result returns to private staging with its source attached.

The tray moves. The customer plaque does not. A fixed plaque above the instrument always reads, in substance:

**Maya Chen · Aperture House · Private Brain**  
**Decision: How can Maya make her quality standard usable by the team?**

The plaque sits outside the tray so customer identity cannot appear to travel with the payload or change silently. A second fixed line names the current audience at every crossing: **For Krish only** or **Customer-visible selection**. The first proof uses **For Krish only**.

The tray carries one material object or one context bundle at a time. A narrow paper-like receipt tears off visually and remains on CTRL's side whenever something enters or leaves. It records what happened without turning the interaction into a confirmation ceremony.

The metaphor is functional:

- the tray shows exactly what is moving;
- the fixed plaque shows whose Brain is active;
- the boundary slot shows when material crosses systems;
- the retained receipt proves what CTRL kept;
- the three resting places make capture, handoff and return different states rather than variations of one upload box.

There is no file-picker modal as the home state. Paste, voice, file and link are ways to place material on the same tray, not destinations in a connector menu.

## 2. Primary interaction

The primary interaction is **place, inspect, pass**.

At rest, the tray is open on CTRL's side with one prompt: **What do you want to add for Maya?** Ordinary paste anywhere in the working field places the pasted fragment directly on the tray and produces a receipt. No submit button follows a normal paste.

Four input paths remain apparent without becoming a toolbar:

- **Paste** is the default and works anywhere in the field.
- **Add a link** focuses one single-line field, then accepts the URL as the original source without claiming to have read the page.
- **Add a file** uses the browser file chooser and shows the file name, type and size in the immediate receipt.
- **Speak** opens a large start and stop control in the same tray. It is active only where the proof can actually capture audio. If microphone capture is unavailable, it is visibly unavailable and names Paste or Add a file as the recovery.

Drop is an extra pointer path for files, never the only path. Every drag or slide gesture has a labelled button and keyboard equivalent. The physical movement teaches the state change, but no meaning depends on animation.

After capture, the next primary action sits on the tray beside the receipt: **Prepare for Claude**. After the proposed context is visible, the action becomes **Use this context in Claude**. After work in Claude, the return state uses **Bring a Claude result back**, followed by one paste. Each state has one primary ask.

## 3. Sequencing and state transitions

The whole loop is one state machine. The Decision Bench remains the stable origin, while the tray changes state.

### State 0: Ready to capture

The customer plaque, private audience and current decision are already visible. The tray asks **What do you want to add for Maya?** Paste is immediate. Link, file and voice paths are available on the same surface.

Transition: deliberate paste, completed file selection, accepted URL or completed voice capture moves to State 1.

### State 1: Pasted material received

The original fragment remains visible in a clipped preview. The retained receipt states:

- **Saved in Maya's private staging**;
- source form and captured time;
- what CTRL could identify from explicit fields;
- **No Brain meaning has been assumed yet**.

The primary action is **Prepare for Claude** when enough explicit context exists. A secondary **Inspect receipt** opens details in place or in an existing dialog. It does not ask for confirmation of facts already known.

Transition: prepare moves to State 2. A material ambiguity branches to State 1A. A duplicate branches to State 1B. Delayed processing branches to State 1C.

### State 1A: One ambiguity needs an answer

The tray stops before staging completes and asks only the question that changes subject, audience, provenance or meaning. Examples include **Is this Maya's wording or your note?** and **Is this for Maya or private to you?**

The answer uses two or three plain chips. **Keep private and unclassified** is the safe exit. The original input remains visible and safe while Krish answers.

Transition: one choice completes the receipt and returns to State 1. No multi-field form appears.

### State 1B: Duplicate source

The retained receipt says **This source is already in Maya's staging** and shows the existing captured time and source identity. No second item is created by default.

The one primary action is **Use the saved copy**. Closing the tray changes nothing.

Transition: use saved copy returns to State 1 with the existing source selected.

### State 1C: Processing delayed but source safe

The receipt says **The source is safe. Reading it is taking longer.** The original input remains inspectable. CTRL does not present extracted meaning, a summary or a ready handoff.

The one recovery action is **Try reading it again**. Krish can leave the tray without losing the staged source.

Transition: successful retry returns to State 1. Continued delay stays in State 1C without clearing the source.

### State 2: Context laid out before handoff

The tray shifts to the boundary slot but does not cross it. Its contents are laid out as a short manifest for one named purpose:

**Purpose: Help prepare the next conversation about Maya's quality standard.**

The default synthetic bundle contains only:

- the consequential decision;
- the current supported read: **The team misses early quality signals**;
- the open question: **What is the first warning sign Maya notices?**;
- at least three explicitly selected source references from the fixture;
- the newly staged fragment when its status permits use.

Directly below, one exclusion is written in full, for example **Not included: Krish's private note**. **Whole Brain** is not a selectable default and is not presented as a shortcut.

The audience, freshness and expiry use one calm line: **For Krish in Claude · checked 2 minutes ago · available for 30 minutes**. The proof uses fixture-driven values rather than claiming security or diagnostic quality.

The primary action is **Use this context in Claude**. **Change what goes** is a secondary inspection action. It opens a single selection state with one ask: **Which sources should go for this purpose?** The current three source references are individually named, private material is unavailable rather than preselected, and the whole Brain cannot be selected.

Transition: use this context moves to State 3. Editing the source selection returns to this state with the manifest updated in place.

### State 3: Ready to use in Claude

The tray crosses the visual boundary and leaves its manifest and receipt visible on CTRL's side. The connector receives a read-only, expiring context selection for the named purpose. It receives no permission to alter the Brain.

The visible result appears beside the action that caused it:

**Ready in Claude**  
**3 sources included · 1 private item excluded · expires at [time]**

The task starter is small. It tells Claude the purpose and how to request the prepared context through the read-only path. It does not place private Brain contents on the clipboard. Automatic prompt submission does not occur.

If the proof can open the supported Claude route, the primary action is **Open Claude** and must work. If it cannot, no active Open Claude control is shown. The primary action is **Copy task starter**, which uses the clipboard and produces State 3A.

The context can be closed early with **Stop sharing this context** in its detail view. That action revokes only this temporary selection and does not remove staged material from CTRL.

Transition: successful use leaves the exchange ready for a return. Clipboard fallback moves to State 3A. Wrong customer or expiry moves to State 6.

### State 3A: Claude unavailable fallback

The response sits at the copy action:

**Claude did not open. The task starter is copied.**  
**Open Claude and paste it. Your private Brain contents were not copied.**

The prepared context remains available until its stated expiry. The one recovery action is **Copy again**. The return path remains available after Krish finishes in Claude.

### State 4: Bring a result back

The tray returns empty to CTRL's side and asks **Bring a Claude result back for Maya?** The one action is a deliberate paste into the return tray. No conversation history is synced and no result is collected in the background.

Transition: paste moves to State 5. Closing the tray leaves no empty record.

### State 5: Returned Claude result in staging

The returned block receives an immediate receipt:

**Claude suggestion · brought back by Krish · [time]**  
**Saved in Maya's private staging · not trusted Brain memory**

The receipt links the return to the exact purpose and context version that left CTRL. It does not claim that Claude originated any quoted customer words unless the selected source already carries that provenance.

The return view uses four fixed source marks wherever those source classes appear:

- **Maya's words** for verbatim customer material already present in the selected sources;
- **Krish's judgement** for Krish-authored notes;
- **CTRL synthesis** for the current supported read or other explicit CTRL interpretation;
- **Claude suggestion** for the entire returned result.

The returned result cannot join the current Brain route, change the Decision Bench or alter trusted meaning from this surface. The primary action is **Finish exchange**, which returns to the Decision Bench with a small staging count. Governed Brain review remains a later, separate workflow.

### State 6: Wrong customer or expired context closes safely

The tray does not cross. The context payload is unavailable to Claude and the visible message names one cause:

- **Closed because Maya is no longer the active customer**, or
- **Closed because this context expired**.

For a wrong-customer state, the one recovery action is **Return to Maya**. It restores Maya as the active customer before rebuilding the manifest. Nothing is shared while identities disagree.

For expiry, the one recovery action is **Prepare fresh context**. It rebuilds from current permitted sources and shows a new manifest before any handoff. The expired selection stays closed.

The original staged input and its receipt remain safe in both cases.

## 4. Information structure

The structure follows the exchange, not a document hierarchy.

### Fixed identity band

This always shows the active customer, organisation, private Brain boundary, current decision, freshness and current audience. It is outside the tray and cannot be hidden by a capture or handoff state.

### Decision reference strip

One compact strip carries the existing Decision Bench context needed to understand the transfer:

- decision;
- current supported read;
- open question.

It is read-only here. Selecting any line opens its existing evidence or Living Brain inspection route. The exchange surface does not create a second interpretation store.

### Transfer bed

This is the only active working region. It shows the current material, context bundle or return result, plus the one primary ask for the current state. Previous and future stages appear only as quiet labels, not as active panels.

### Retained receipt edge

The receipt remains visually attached to CTRL's side. It answers, according to state:

- what was captured;
- where it is held;
- what CTRL has not assumed;
- what crossed to Claude;
- what remained excluded;
- what came back and who authored it.

### Boundary slot

The boundary is the only point where a transfer changes audience or system. It carries the plain audience, freshness and expiry line. It does not show MCP names, schema fields, provenance IDs, tokens or security claims unless Krish deliberately opens technical details.

## 5. Desktop behaviour

At 1440 by 900, the interaction occupies one fixed working frame attached to the icon-only operator shell. The page does not scroll during the primary exchange.

- **Shell rail:** the approved icon-only rail remains unchanged.
- **Identity band:** 64 px high across the available width.
- **Decision reference strip:** 96 px high, with the decision, current read and open question on one readable line each.
- **Exchange field:** the remaining height holds one wide transfer instrument with generous internal spacing. The retained receipt occupies the left third, the active tray the centre and the current destination or return status the right third.
- **Status edge:** a narrow bottom line carries save state, freshness, keyboard hint and closed or delayed status.

Only the active tray region looks actionable. Receipt and destination regions are readable evidence, not a field of equal cards. Source details and context selection may use the existing dialog primitive, but capture itself never begins in a modal. No dialog contains a nested scrollbar. Long content uses a clipped preview with **Inspect full source**, while the source detail follows natural document movement.

Keyboard order follows the state: identity, active material, one primary action, one secondary inspection action when present, status. Paste works when focus is anywhere inside the exchange field. Escape closes an inspection dialog and never discards captured input.

Motion is one short tray movement after a completed action. Reduced motion swaps it for an immediate position change and text status. Colour is never the sole carrier of state.

## 6. Mobile behaviour

Mobile keeps the physical transfer logic but removes the wide counter.

The fixed top strip shows **Maya Chen**, **Private Brain** and the current audience. The decision sits directly below in one compact block. The active tray then fills the natural page width and presents only the current state.

At capture, Paste, Link, File and Speak appear as four labelled 44 px controls in a two-by-two arrangement, with Paste still working directly in the field. At receipt, the captured fragment comes first, followed immediately by what was saved and not assumed. At handoff, purpose appears before the three selected sources, explicit exclusion, audience and expiry. At return, the Claude suggestion label and staging boundary appear before the result preview.

The primary action stays after the exact content it affects. It may be sticky only while the content remains visible above it and never covers the receipt. Mobile uses no horizontal dragging, nested scrolling or squeezed graph. A labelled **Move tray** action replaces the desktop slide gesture. Touch and keyboard paths remain complete at 390 by 844 and 320 by 568.

The Living Brain route opens as the existing ordered relationship view. Returning from it restores the same exchange state and source selection.

## 7. How the exchange remains legible

### What CTRL captured

The original input and retained receipt remain together. The receipt gives source form, captured time, private staging state and explicit non-assumptions. A link receipt says the URL was saved, not that the page was read. Delayed extraction never masquerades as understanding.

### What Claude receives

Before handoff, the tray shows the named purpose, current read, open question, every selected source reference and at least one explicit exclusion. The count beside **Use this context in Claude** must match the visible manifest. Audience, freshness and expiry remain visible before and after the action.

### What came back

The return receipt labels the complete result as **Claude suggestion**, records that Krish brought it back, links it to the outbound context version and keeps it in private staging. Maya's words, Krish's judgement and CTRL synthesis retain their existing marks inside quoted or referenced context. No source class is inferred from writing style.

## 8. Failure and recovery contract

| Failure or edge state | What remains visible and safe | One recovery action |
|---|---|---|
| Genuine ambiguity | Original input, private staging boundary and the one disputed field | Answer one plain chip question, or keep private and unclassified |
| Duplicate source | Existing source identity and captured time | Use the saved copy |
| Processing delayed | Original source, receipt and last completed state | Try reading it again |
| Claude unavailable | Prepared context, expiry and copied-task status | Copy task starter again |
| Clipboard denied | Context remains ready and no Brain contents are exposed | Select task starter text |
| Operator-private item selected by mistake | Item stays on CTRL's side and the manifest cannot complete | Remove the private item |
| Wrong active customer | Both customer names, closed transfer and retained receipt | Return to Maya |
| Expired context | Closed context version and unchanged staged material | Prepare fresh context |
| Stale selected source | Source date and stale status, with no safe-completion mint | Replace or remove the stale source |
| Return paste fails | Original clipboard content remains outside CTRL and no empty record is created | Paste again |
| Unknown return provenance | Result remains private and unclassified | Name its source before staging |
| Connector or page error | Last verified receipt, exact failed region and no active transfer claim | Retry the failed step |

Failure never clears the original input, switches customer silently, broadens the selected context, extends expiry or converts returned work into memory.

## 9. Required state coverage

| Required proof state | Exchange Tray expression |
|---|---|
| Ready to capture | Open tray on CTRL's side with Maya, private audience and one capture ask visible |
| Pasted material received | Immediate retained receipt with original fragment and non-assumption statement |
| Ambiguity that genuinely needs one answer | Tray stops at the boundary and asks one subject, audience, provenance or meaning question |
| Duplicate source | Existing receipt is shown and no new staged item is created by default |
| Processing delayed but source safe | Source remains visible; extracted meaning and handoff remain unavailable |
| Ready to use in Claude | Exact purpose, selected source manifest, exclusion, audience, freshness and expiry sit beside the action |
| Operator-private content excluded | Named private item remains on CTRL's side and is unavailable in the outbound manifest |
| Copied task starter and Claude unavailable fallback | Plain result beside the copy action states that only the task starter was copied |
| Returned Claude result in staging | Return receipt marks the full result as a Claude suggestion supplied by Krish and not trusted memory |
| Wrong-customer or expired-context failure | Boundary closes, nothing crosses and one identity-safe or freshness-safe recovery is offered |

## 10. Fit with Decision Bench and Living Brain

The Exchange Tray begins from the active Decision Bench, not from global navigation or settings. The decision, current read and open question are passed into the fixed reference strip. A source selected for Claude can be inspected through the existing evidence detail and focused Living Brain relationship route. That preserves the approved Brain as the source of current meaning.

The tray does not add a second graph, a new confidence score or an independent context library. Capture produces private staged material. The Decision Bench continues to own current decision meaning. The Living Brain continues to own typed, directed relationships and evidence. Governed review remains the only later route by which staged material could alter durable Brain truth.

## 11. Real implementation feasibility

This concept is feasible as a synthetic vertical slice using the substrates named in the brief.

### Existing React Decision Bench

- Mount the Exchange Tray as a route or working mode attached to the active customer state.
- Reuse the fixed shell identity, current decision, supported read, open question, source references and focused Brain inspection entry points.
- Keep tray position, source selection, context expiry and return state as local proof state.
- Do not alter the approved Decision Bench information model or imply finished global navigation.

### Synthetic fixture

- Maya Chen, Aperture House, the consequential decision, current read and open question come directly from the required proof data.
- The three selected references, explicit exclusion, audience, timestamps, expiry and source-class marks must be explicit fixture fields.
- Capture, ambiguity, duplicate, delay, connector availability, wrong-customer, expiry and return outcomes are deterministic fixture cases. They demonstrate interaction state only.
- No model-generated summary, diagnostic score, source fetch, speech transcription, customer-value claim or inferred authorship is needed.

### Existing dialogs

- Use dialogs only for source inspection, changing the selected context, viewing the retained receipt or confirming early context revocation where the existing primitive supports it.
- Do not use a dialog as the default capture surface.
- Dialog close must restore the same tray state and must never lose typed or pasted material.

### Read-only MCP substrate

- Expose only the selected purpose-bound context to Claude through an expiring, revocable read path.
- The read path cannot write a Claude result back, mutate the Brain or widen its own scope.
- Manual return paste is therefore the honest first-slice path.
- The task starter may identify the prepared context through the supported read path, but the clipboard contains no private Brain payload.
- Connector names and technical identifiers remain inside deliberate detail inspection, not the daily surface.

### Browser capabilities and active controls

- Paste handling, Clipboard API copy, file input, local URL receipt, buttons, focus management and deterministic state changes are sufficient for the core proof.
- Voice appears active only when browser audio capture can be completed. Otherwise it is visibly unavailable with a working alternate path.
- An Open Claude control appears active only if the proof environment has a working route. Otherwise Copy task starter is the sole active handoff control.
- Every visible action produces an immediate state change or a plain failure result beside the action.

No production connector, automatic prompt injection, conversation sync, background return, trusted-memory write, whole-Brain export, new schema or real customer data is required.

## 12. Hard-failure audit

| Hard failure | How the concept prevents it |
|---|---|
| Whole-Brain or vague automatic context sharing | The manifest names one purpose, each selected source and one explicit exclusion. Whole Brain is not offered as a default or shortcut. |
| Trusted-memory write-back | Every return is a Claude suggestion in private staging. Only a later governed review could change durable truth. |
| Unclear active customer | The fixed Maya plaque sits outside the moving tray and remains visible before capture, handoff and return. Identity mismatch closes the boundary. |
| Technical setup as the daily experience | The daily loop is place, inspect and pass. Connector and provenance identifiers stay in deliberate details. |
| More than one primary ask per state | Each state has one written ask and one primary action. Inspection, close and safe exit remain secondary. |
| Generic upload or chat UI with no product-specific idea | A single pass-through tray links Decision Bench meaning, minimum context selection, retained receipts and provenance-preserving return. There is no transcript, composer or upload modal home. |
| Active-looking control that cannot work in the proof | Voice and Open Claude are active only when supported. Otherwise their unavailable state names a working alternate. Every other active control maps to deterministic local behaviour. |
| Product claims unsupported by synthetic data | The proof claims only that a synthetic source moved through the defined states. It makes no claim about diagnostic quality, customer value, model accuracy or production security. |

## 13. Why this is not a conventional shell

It is not an upload modal because capture is only the first resting place. The retained receipt, bounded outbound manifest and attributed return are part of one continuous instrument. The original input remains visible while the meaning and audience boundary are inspected.

It is not a chat composer because there is no transcript, assistant persona, turn history or open prompt. Claude receives one named task and a deliberately selected context slice. A result comes back only through an explicit return action.

It is not a settings integration page because no connector is configured in the daily flow. The operator handles one real piece of work for one active customer. Technical details appear only on deliberate inspection.

The governing object is the moving context bundle. The governing action is passing that bundle across a visible boundary. The governing state change is receipt retained here, minimum context made available there, suggestion returned here. That full circuit is the product-specific interaction idea.

## 14. Strongest failure risk and kill test

The strongest risk is ceremony. A physical tray can become a charming animation wrapped around three ordinary forms, slowing down the exact circulation it should simplify. The second risk is false reassurance if the boundary looks secure while the source selection or audience is not actually inspectable.

The mitigation is strict: an ordinary paste produces a receipt with no submit step; the proposed Claude bundle is already reduced to the current decision; the user sees the exact manifest before one handoff action; and return is one explicit paste. Motion lasts only long enough to show a completed boundary crossing and disappears under reduced motion.

The concept fails before rendering if any of these become necessary:

- a capture modal before paste;
- a multi-field metadata form;
- a connector setup screen inside the daily loop;
- more than one confirmation after the manifest is visible;
- an inferred source, audience, purpose or authorship label;
- a whole-Brain option used to make selection easier;
- automatic return from Claude;
- a returned result entering trusted memory;
- an active voice, file, copy or Claude control that does not work in the proof.

The cold comprehension test is simple. Give the synthetic frame to a nontechnical viewer and ask four questions after ten seconds:

1. Whose Brain is active?
2. What was saved and where?
3. Exactly what will Claude receive, and what stays out?
4. What is the status of the work that came back?

If the viewer cannot answer all four without a walkthrough, the exchange metaphor has failed and should not proceed to a rendered synthesis.
