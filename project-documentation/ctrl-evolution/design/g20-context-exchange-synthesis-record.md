## Distance result

All pairs passed the minimum two-axis distance gate. The tray and thread share a linear circulation family but differ materially in the primary interaction, information structure and state model. The aperture differs from both on at least four axes. The set was not superficially convergent.

## Selected governing rule

One physical tray carries one exchange. The customer identity and audience remain fixed. Material moves; the customer does not. A retained receipt stays on CTRL's side and answers what was captured, what Claude may see, what stays private and what came back.

The proof is killed if the tray adds ceremony to ordinary paste or if the user notices motion before understanding the boundary.

## Corrections before render

The two judges independently found the same preservation defect in the source concept. The synthesis corrects it:

- original input is saved into the narrowest private staging state before any ambiguity question;
- an unclear returned result is also preserved privately before provenance is clarified;
- operator-private material cannot be selected in the normal handoff UI;
- wrong-customer state closes the tray and requires an explicit return to the frozen customer;
- no customer relabelling, whole-Brain shortcut or automatic prompt submission exists.

## Forbidden hybridisation

- no continuous thread, milestones or numbered progress rail;
- no aperture over the Living Brain and no graph-object selection as the normal path;
- no three-metaphor animation;
- no connector picker, prompt composer or settings setup inside the daily flow;
- no full Brain export beside the task starter;
- no customer preview, correction workflow or trusted-memory approval in this first proof;
- no active control unless its mock behaviour works.

## Feasibility and data truth

The mock uses a deterministic synthetic Maya fixture and browser-local view state. It can truthfully prove interaction comprehension, not production capture, context compilation, encryption, expiry, revocation, MCP access or diagnostic quality.

The existing React Decision Bench, dialog patterns, icon asset and read-only MCP foundation make the later implementation feasible. The proof will not call them. It will simulate the exact required states and label itself synthetic.

Browser paste, file metadata, URL capture, clipboard and microphone permission have real client-side paths. If a capability fails, the proof preserves the source or prepared context and shows one plain recovery action. No prompt is submitted into Claude. Opening Claude, if offered, is a normal link after the starter is copied.

## Render contract

The R1 proof must show the complete circulation loop in one playable artifact:

1. capture a synthetic fragment through paste, example, link, file or voice;
2. receive a private-staging receipt;
3. inspect a deterministic handoff containing the decision, current read, open question and three exact sources;
4. see one operator-private exclusion beside the handoff action;
5. copy a small task starter;
6. paste a Claude result back;
7. receive an amber, non-memory return receipt with four provenance roles;
8. finish back at the Decision Bench context.

Wide-screen target is no-scroll at 1440 by 900. Mobile uses progressive disclosure and natural page movement at 390 by 844 and 320 by 568. Keyboard, focus, 44px targets, reduced motion, overflow, duplicate, delayed, wrong-customer, expiry and clipboard recovery are included in verification.
