## Governing synthesis

The functional proof will use one spine only:

`owned call at Now -> recorded context -> exact supported relationship -> source -> correction -> past preserved and current use changed -> repair receipt -> wider Living Map`

The wake is the opening state of the My calls portrait, not a third product mode. The same selected decision enters the Living Map.

## Required corrections before rendering

The original temporal concept contains phrases that could imply unsupported causality. The proof must:

- replace “Show what shaped this” with neutral recorded-context language;
- remove “recorded cause or consequence” entirely;
- label the aim and standard as recorded with the call;
- reserve “supports” for the exact `item:item-standard@v1 -> item:item-aim@v1` relationship;
- avoid drawing a semantic edge from either item to the decision;
- state that the current decision is the projection focus because it is relevant to the active marketing task, not because CTRL knows the complete causal story; and
- fail closed if the portrait and map reference different canonical versions.

## Bounded borrows

These strengthen the chosen spine without hybridising it:

- a stable selected standard during source inspection and correction;
- inline relationship meaning and evidence at the relationship itself;
- Before and From now on labels in the correction preview;
- selective movement only for the two replaced relationships while the unaffected tension stays still;
- Find in my Brain and Return to this decision only after the Living Map opens;
- a narrow-screen linear reading order for every relationship;
- explicit Repair incomplete if any dependency lacks a terminal receipt; and
- preservation of the last verified view if parity fails.

The proof must not import a four-lens rail, map-first opening, free panning as the main mobile action, folded page, atlas, paper or open-and-trace interaction.

## Functional proof contract

The proof uses the real `LB01` and `LB04` wording and outcomes. It must let the user:

1. identify the owned call;
2. reveal only context recorded with it;
3. distinguish the one exact supported relationship from co-present context;
4. inspect its source;
5. narrow the standard in one tap or edit it in ordinary language;
6. see the prior meaning remain historical while the new meaning becomes current;
7. see Portrait and Living Map rebuild;
8. see the Board brief and shared release require review; and
9. enter the Living Map with the same selected decision and only the three fixture-backed relationships.

The proof also needs controls for reset, direct state selection and reduced motion so verification can inspect every state deterministically.

## Visual direction

Retain the approved CTRL floor: deep ink, warm paper, mint for accepted current state, amber for what changed, purposeful thin-line iconography and quiet state-responsive motion. The temporal path must feel editorial and instrument-like, not like a project timeline or workflow diagram. No sparkle symbols, gradient spectacle, glass panels, mascot, chat-first frame, floating dashboard cards or ambient node drift.

## Pass and flip rule

The selected concept passes the human gate only if a cold user understands:

- these items were recorded with the decision;
- the standard supports the aim;
- CTRL is not claiming that it knows the complete reason for the decision;
- the correction changed current and future use without rewriting the past; and
- two consequential artifacts still need human review.

If the temporal order is interpreted as proof of why the call was made, reject this spine. The named fallback is the fixed-object concept in [`g13-concept-l.md`](g13-concept-l.md), not a more heavily explained version of The Wake.
