## Why R80 exists

R79 repaired many R78 defects but all seven durable roles still found escape routes. Its overlay could inherit contradictory rules, and several declared safeguards were not the programs the checker actually executed. R80 removes that ambiguity. It materializes one effective contract and imports only six exact, named R79 sections from the frozen R79 commit. Every other rule is replaced by an R80 module.

R78 and R79 remain useful history. Neither is effective authority.

## What is now executable

- Every server-owned lifecycle dependency has one exact owner, fact kind, source type, issuer rule and policy version. Runtime owner substitution fails.
- Normative receipts resolve a real authentication event, recompute their own fingerprint, hash the actual before and after accepted-decision bytes, derive the real material delta and bind the exact visible consequence.
- A free-form answer can steer only after the same authenticated human confirms the verbatim expression, its structured interpretation and the visible consequence.
- Final transition authority resolves every actor against the transition's exact `all` or `any_one` rule, authenticates each actor and enforces strict expiry at commit time.
- Routing distinguishes server-verifiable gaps from human-owned judgement. It counts exact unresolved facts, never answer-kind labels, and never queues another customer question automatically.
- Question validation reads the actual payload. It checks length, answer count, case-specific wording and same-case material decision effects. Unknown and unconfirmed free expression have no satisfaction effect.
- Predicate evaluation executes the contract's disposition map, precedence and result map. A mutation proving that `missing` means `present` breaks the committed vectors.
- Correction seals canonical dependency tuples, including edge kind, and joins exactly one non-steering terminal receipt to each tuple.
- External consistency begins unreserved and explicitly covers reservation, authority acquisition, provisional local commit, protocol-specific finality, second compare-and-set, lost acknowledgement, rollback, abort and quarantine. No external fact kind is currently authoritative.

## Human experience protected

The machinery stays backstage. A leader should see one clear, case-specific question only when one answerable human judgement can materially sharpen the consequential decision. Two unresolved facts of the same kind remain two facts and become a safe hold or one Krish-led session agenda. Server gaps never masquerade as questions. The default surface remains one heading, one question, one answer group, one optional note and one primary action.

The reference case asks what proof would justify rebuilding Aperture House's marketing team. Each normal answer changes the same accepted decision's route and proof obligations. Generic wording, excessive copy, invented dependencies and cross-case effects fail.
