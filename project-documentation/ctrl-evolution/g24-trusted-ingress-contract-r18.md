## Case history remains history

Case rotation no longer updates a prior row. It appends one new row at a database-generated transaction time strictly after the selected prior row. Backdating, future scheduling and caller-supplied validity are forbidden. Historical snapshots therefore continue to select the row that genuinely existed then.

The control request now has a complete fingerprint. A closed append-only receipt binds the request, prior row, new row and server time. The same scoped key and same request returns the exact receipt without a write; the same key and a different request holds as a collision. Binding and receipt commit together or neither exists.

Only the current Krish operator may rotate an existing case. No model, workload, browser, edge or generic service principal may call the control plane. Bootstrap remains migration-identity-only at this local seam and is not a production onboarding design.
